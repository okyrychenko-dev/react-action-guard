Every measured production metadata update rendered zero boolean consumers and exactly one render per metadata/button consumer, for both related and unrelated scopes. Availability removal rendered each consumer once and made every checkout button available. Observer/publication counts, blocker counts, priority ordering, scoped availability and related reasons passed validation. Five observation leases are present in the medium/large workloads; these are public observer leases, not a rendered Devtools panel.

**Source observation:** `useBlockingInfo` observes the shared snapshot and filters/sorts again when it changes; UI `useTopBlocker` also observes the snapshot and recomputes scoped metadata. **Inference from measurements:** repeated metadata work is a stronger follow-up candidate than cached snapshot retrieval or lifecycle projection alone. These separate scenarios do not isolate sorting from scope matching, React from selector evaluation, or browser paint. The workload intentionally concentrates many consumers on one scope and does not establish that every application is slow.

Development Strict Mode is a diagnostic run, not the production budget: unrelated updates produced two renders per metadata/button consumer and zero boolean renders. Its p95 values were 14.101, 144.870 and 3027.278 ms; the large tail illustrates how costly/noisy development diagnostics can be. Raw development samples are retained separately and must not be mixed into production summaries.

**Decision threshold:** investigate when an unrelated update exceeds a 16 ms p95 budget at 100 consumers per kind / about 100 active blockers, or when an application's own representative workload shows unwanted unrelated renders. This run exceeds that threshold. Before changing subscriptions, repeat the workload on the target browser/hardware and require a prototype to reduce unrelated commit p95 by at least 50% while preserving priority, global/multiple scopes, confirmation, timeout, cleanup and provider isolation. Prefer exploring shared/cached scoped metadata first; these results do not prove a scope index is the right solution. No optimization is implemented by this assessment.
